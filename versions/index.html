5. 无 AI 排程引擎（10 步流程；P = 0.35 紧迫 + 0.30 难度 + 0.20 重要 + 0.15 拖延；权重可配置；

  • 重大 25. 统一完成链路：记录时段 / 标记完成 / 清理依赖 2026-10-22 · 版本 57–58
    我给你的原始 prompt（点开） 
    三件事大概率是同一个数据链路问题：
1. 计划页点「完成」只完成了"时段"，没有完成"任务"——任务状态仍是 not_started/in_progress，
   所以还出现在前置任务候选里，花园清单也仍显示（剩余 0 被 Math.max(1, remaining) 兜成 1 分钟）。
2. 花园计时完成只改了任务状态，没有写入学习记录——completeStudyTask 里 actualMinutes 被 void 丢弃，
   而统计只统计 state === 'completed' 的时段。
要求：把"完成任务"收敛成一条统一链路：记录实际学习时段 + 标记任务完成 + 取消剩余时段 + 清理依赖，
计划页和花园计时都走它。

1. 计划页「完成」= 完成整个任务：同时提交 session.complete（写 actualMinutes）与 task.status→completed，
   由 reconcile 取消剩余时段，并从其它任务 dependsOn 移除；顺序必须先时段后任务；
   session.complete 失败则整体失败；仍走预览/确认链路；完成后刷新页面、表单候选与花园面板。
2. 花园计时完成/提前完成都必须写入统计：优先复用任务已有未完成时段（listStudyTasks 增加 sessionId）；
   没有时段时补一条合法 completed 记录（date/startMinutes/endMinutes 允许跨午夜、
   plannedMinutes、actualMinutes、state、locked、source、时间戳）；实际分钟取真实用时，
   最小 1、不超过剩余；原子提交；幂等（已完成直接返回 already）。
3. 前置候选与花园清单过滤"已完成 / 0 剩余"：候选要同时满足状态有效与 remainingMinutes > 0
   （建议用 listTaskViews）；花园只列剩余 > 0 的任务，不能造"1 分钟"假任务；返回 sessionId。
4. 刷新：计划页完成/应用预览后，若花园 iframe 已存在要刷新面板清单，不要只依赖重新进入花园。

约束：不删已完成任务与历史；不改排程引擎优先级；不引入依赖；所有完成路径走同一个服务；
时间计算复用 domain/time.js；实际分钟必须校验（不得负数、0 长度、超过 8 小时）。
    解决了什么completeTaskAtomic：复用或补登 completed 时段 → 标记完成 → reconcile 取消剩余 → 清理依赖，一次 commit 原子提交；花园计时计入统计；过滤 0 剩余；应用预览后即时刷新花园面板；补齐跨午夜记录与刷新测试。

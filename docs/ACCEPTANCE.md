# 验收用例与测试映射（ACCEPTANCE）

本文件是"需求 ↔ 测试 ↔ 实现状态"的对照表，用于回答两个问题：

1. 每条需求有没有对应的自动化测试？
2. 现在到底验到了什么程度（哪些是自动化通过、哪些需要人工确认、哪些还没实现）？

**状态图例**

- ✅ **自动化通过**：有测试文件与断言，`node --test "tests/**/*.test.js"` 全绿。
- 🟡 **部分自动化**：核心逻辑已测，但依赖阶段 2/3/4 的部分尚未实现。
- ⏳ **待实现**：功能本身尚未开发（阶段 2–4）。
- 👤 **需人工确认**：涉及真实浏览器渲染与交互，需按"人工验收步骤"操作。

## 三、人工验收步骤（阶段 1 可验证的部分）

### 准备

```bash
node scripts/serve.mjs          # 记住启动时打印的地址，默认 http://127.0.0.1:4173/
```

在浏览器打开该地址。**建议先打开开发者工具的控制台**，确认没有红色报错。

### A. 页面与状态

| 步骤 | 预期现象 |
|---|---|
| A1 | 打开首页 | 显示"今日总览"，左侧导航有 6 项，顶栏显示今天日期与"尚未生成正式计划" |
| A2 | 依次点击 6 个导航项 | 每页都有明确标题与内容，不出现白屏或报错 |
| A3 | 直接访问 `#/not-exist` | 显示"页面不存在"提示，仍可正常导航（不会崩溃） |
| A4 | 缩小窗口到 < 900px | 侧边导航变为顶部横向标签，网格变单列，页面仍可读 |

### B. 任务管理

| 步骤 | 预期现象 |
|---|---|
| B1 | 任务列表 → "新建任务"，名称/科目留空直接提交 | 表单顶部列出需要修正的字段（带错误码与字段名），不写入数据 |
| B2 | 填写：名称"测试任务"、科目"数学"、预计 90 分钟、截止日期填 `2025-02-30` | 提示"不是真实存在的日期"，不写入 |
| B3 | 改为合法日期与时间后提交 | 出现成功提示，任务出现在列表中；显示"剩余 1 小时 30 分钟" |
| B4 | 刷新页面 | 任务仍在（验证持久化） |
| B5 | 点击"编辑"，把预计用时改为 120，勾掉"允许拆分" | 保存成功；最短/最长时段自动变为 120（不可拆分任务必须一次排完） |
| B6 | 再建一个任务，在其"前置任务"里选中 B2 的任务 | 保存成功（合法依赖） |
| B7 | 编辑第一个任务，把它的前置任务设为第二个任务 | 被拒绝，提示"前置任务之间存在循环依赖：…" |
| B8 | 对第一个任务点"标记完成" | 状态变为已完成；列表中按筛选"已完成"仍能看到 |
| B9 | 对已完成任务点"取消任务" | 被拒绝，提示状态不能从已完成直接变为已取消 |
| B10 | 点"删除" | 弹出确认框，**逐条列出影响面**（待进行时段数、已完成记录数、锁定数、依赖它的任务）；不勾"我已了解"则"彻底删除"按钮不可点 |

### C. 偏好设置

| 步骤 | 预期现象 |
|---|---|
| C1 | 偏好设置页 | 顶部列出每天的可学习时间（默认 16:00–23:00）与排程参数 |
| C2 | 把 JSON 编辑区里的 `bufferRatio` 改成 `0.9` 并"校验并保存" | 提示缓冲比例必须在 0–0.5 之间，**设置未被保存**（可点"恢复为当前值"确认） |
| C3 | 把某一天的 `studyWindows` 改成 `[]` 并保存 | 保存成功并提示"所有日期都没有可学习时间…"这类提醒（属于合法但会导致排不出的配置） |
| C4 | 点"恢复默认设置" | 二次确认后设置回到默认值；任务与计划历史不受影响 |

### D. 计划与版本

| 步骤 | 预期现象 |
|---|---|
| D1 | 七天计划页 | 显示 7 天表头与 06:00–24:00 的小时刻度；无计划时显示空状态说明 |
| D2 | 点"上一周 / 下一周 / 回到本周" | 表头日期随之变化；切到未来周时提示"正式计划没有覆盖这一周" |
| D3 | 调整预览页 | 显示空状态（阶段 1 没有正式计划）；版本历史为空时不显示该卡片 |
| D4 | 点"撤销上一步" | 按钮为禁用状态（没有可撤销的版本） |

### E. 数据安全

| 步骤 | 预期现象 |
|---|---|
| E1 | 顶栏"导出备份" | 下载 `七天学习规划器-备份-YYYY-MM-DD.json`；偏好设置里"上次导出备份"更新 |
| E2 | 用文本编辑器把该文件改成非法 JSON，再"导入备份" | 提示导入失败且**现有数据未做任何修改**（列表中的任务仍在） |
| E3 | 用合法的备份文件导入 | 提示导入成功与任务数量；数据被整体替换 |
| E4 | 导出后清空浏览器数据并刷新 | 数据为空（符合预期）；再导入备份文件可完全恢复 |

### F. 自动化界面冒烟（无需浏览器）

```bash
node --test tests/integration/ui-smoke.test.js
```

预期：3 个测试全部通过。它使用最小 DOM 打桩让 `src/main.js` 真正执行，验证外壳渲染、
六条路由逐条渲染不抛异常、未知路由给出"页面不存在"提示、时间轴有 7 个日期表头与 18 个整点刻度、
空数据时各页都有空状态。**它不能代替下方的浏览器人工验收**（CSS 布局、真实点击、焦点行为不在覆盖范围内）。

### G. 单文件版本

| 步骤 | 预期现象 |
|---|---|
| F1 | 运行 `node scripts/build-standalone.mjs` | 输出"已生成 dist/standalone.html（… 内联 32 个模块）" |
| F2 | 双击 `dist/standalone.html` | 页面外观与功能与服务器版本一致，无控制台报错 |

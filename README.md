# 七天学习规划器

面向学生的**七天学习时间规划 Web 应用**。输入学习任务、截止时间、固定活动、可用时间与个人偏好，
由**确定性的规则算法**（不含任何 AI 模型或外部 API）生成未来七天的学习计划，并在任何改动生效前给出
可对比的调整预览，只有用户确认后才替换正式计划。

所有数据都保存在你自己的浏览器里，不会上传到任何服务器。

**现在已经能做什么**

- **自动生成七天学习计划**：在"今日总览"或"七天计划"点"生成计划"，
  引擎会按任务截止时间、难度、重要程度、拖延风险、固定活动与可用时间算出候选计划。
- **调整预览**：候选计划与当前正式计划的差异逐条列出（新增 / 移动 / 时长调整 / 拆分 / 取消 /
  锁定时段影响 / 每日学习量与休息缓冲变化 / 无法安排的任务与原因 / 截止风险评估），
  由你点"确认应用"或"放弃修改"。
- **硬约束保障**：学习时段永不与固定活动重叠，锁定与已完成时段永不被自动移动，
  不可拆分任务不会被切开，依赖顺序与时长限制都会被校验（H1–H10，含负向测试）。
- **确定性与可解释**：同样输入必然产出同一计划（派生 ID 由输入指纹推导）；
  每个未安排任务都有原因码、中文说明与可选处理建议；超载时如实报告，不偷偷取消缓冲。
- 完整的领域数据模型、校验逻辑、本地持久化（自动备份 / 损坏恢复 / 导入导出严格校验）、
  六个页面与小时刻度时间轴、任务表单、危险操作二次确认。
- **489 个自动化测试**（含 H1–H10 的负向测试、草稿事务性测试与单文件产物的真实执行测试）。

**v0.3：界面与预览交互**

- **所有修改都先生成预览**：新建/编辑/完成/取消/删除任务、锁定/移动/取消时段、
  增删改固定活动、修改可学习时间与排程参数——全部先变成候选计划 + 差异预览，确认后才写入。
- **每日视图**：单日时间轴 + 当日容量构成 + 可逐段操作的时段清单 + 当天固定活动。
- **时段详情抽屉**：锁定 / 解除锁定 / 移动（可保持锁定）/ 取消 / 标记完成，并解释每条安排的原因。
- **固定活动管理页**：按类型筛选、删除前显示"能释放多少可用时间"、全周占用与净容量概览。
- **图形化偏好设置**：逐日可学习时间编辑器、排程参数、休息规则、优先级权重（JSON 编辑降级为高级入口）。
- **版本历史页**：当前版本指标、历史版本列表与变更说明、撤销、清空历史、受保护学习记录统计。
- **窗口滚动**：把计划窗口前移/后移一天，保留已完成历史并重新规划未来七天。

**v0.4：学习计时与数据维护**

- **完整的学习计时工作台**：开始 / 暂停 / 继续 / 结束，显示剩余时间、已专注时长、任务剩余与锁定状态；
  计时状态持久化——刷新页面后从累计分钟数继续，不会归零。
- **结束时的分支处理**：提前完成、按时结束、超时三种情况都会列出可选处理方式
  （记录实际时长 / 重新规划剩余工作 / 标记任务完成 / 延长本段），每条都写明后果；
  **只有"只记录实际时长"立即写入，其余一律先生成候选计划预览**。
- **存储与备份面板**：显示存储占用、浏览器配额、上次导出时间，并在久未备份时提醒。
- **历史清理入口**：清理"已取消且从未开始过"的时段记录、把版本快照裁剪到最近 N 个；
  清理前给出影响面表格（会删多少条、释放多少分钟），必须勾选确认才会执行；
  **已完成的学习记录与当前正式计划永远不在清理范围**。
- **导入两步走**：先预览（包含什么、有什么警告、会不会覆盖），确认并勾选"我了解会覆盖"之后才写入；
  校验失败会逐条列出错误，现有数据一个字节都不变。

**v0.5：写入路径合并与可访问性**

- **计时每秒实时更新**：计时进行中，剩余时间每秒跳动；暂停或未开始时不做无谓刷新。
- **键盘完全可用**：`1`–`9` 按导航顺序切换页面、`g` 生成/重新规划、`?` 显示快捷键帮助；
  在输入框里按键不会被拦截。侧边导航项右侧显示对应数字，功能可被发现。
- **可访问性**：时间轴可聚焦并用键盘滚动；每个时段块都是带完整无障碍名称的按钮
  （类型｜任务｜时间｜时长｜是否锁定）；倒计时带 `role="timer"` 与 `aria-live`；
  关键状态变化通过状态区播报。
- **写入路径唯一**：任务服务的写入也改为复用 `domain/mutations.js`，
  "预览看到的"与"确认后写入的"由同一段代码保证一致。

**仍然不做（有意为之）**

- 时段拖拽绘制（第一版不做清单）、撤销后的重做（redo）、自动清理历史记录。
- 不引入任何构建工具与运行时依赖。

**v1.3.0 的变化**

- **修好了"添加休息点了没反应"**：界面服务里引用了不存在的变量，点保存就抛异常且被吞掉；
  现在保存失败一定会显示错误，不会再出现"点了没反应"。
- **「设置休息」一个入口两种含义**：仅今晚（一次性）/ 固定睡觉时间（每周重复），不会互相混淆。
- **历史不再锁死时间**：已完成 / 已删除任务占过的时段，不再阻止你在同一时间安排固定课程或休息。
- **规划开始时间**：可指定，也可留空（默认从"当前时刻之后的下一个整点"开始）；不会排到过去。
- **科目管理**：科目改成统一列表，可改名（引用它的任务一起变）、可删除（仍被使用时先拦住）。
- **统计柱状图**：改成一天一根柱子（实际时长），计划时长用同列浅色轨道表示，不再"一高一低"。
- **偏好设置精简**：删除了「可学习时间（按星期）」区块（底层数据保留，排程仍在使用）。

**v1.2.0 的变化**

- **界面不再发蒙**：壁纸层改为 `z-index: -1`（原先画在内容之上，把整页糊住了），
  并移除了卡片上的 `backdrop-filter` 与半透明底色。
- **计划里可以直接删任务**：每张学习卡片都有「详情 / 完成 / 删除任务」，

- **完成后从计划里消失**：标记完成的任务不再出现在任何日期列，已完成的学习记录保留。
- **没有时间列和时间刻度了**：时间轴组件与样式已彻底删除，时间只显示在卡片内部。
- **固定任务跨周正常**：按重复规则实时展开，翻到下一周依然显示。
- **名称统一最多 10 个字符**（任务 / 固定任务 / 休息），界面与校验用同一个常量。
- **卡片尺寸有基准**：5 分钟 = 一个标准格，卡片高度严格按时长取整数格。
- **新增休息时间**：独立颜色与标签，跨午夜自动拆成两个日期区块（22:00–24:00 / 00:00–08:00）。

**v1.1.0 的变化**

- **修复数据一致性**：完成任务、改小工作量、填"已完成时长"时会同步取消超出的未完成时段，
  不再出现"未完成时段 120 分钟但剩余 0 分钟"、任务删不掉、重开应用数据读不出来的问题。
- **修复壁纸显示**：原因是背景层节点从未创建；现在上传即可见、刷新后仍在，
  图片丢失时安全回退。同时移除了「显示方式与文字可读性」设置，壁纸固定为填充 + 固定遮罩。
- **移除缓冲时间**：不再预留、不再生成缓冲时段；设置、统计、预览、每日视图里的缓冲全部去掉。
  休息（计划休息）与缓冲是两件事，休息完整保留。
- **移除番茄钟与奖励转盘**：页面、入口、计时逻辑、相关状态与统计一并删除；
  **普通学习记录、任务完成记录与学习统计全部保留**。
- **每日视图重设**为「日期为列、任务为内容」：每列一天，列里按时间列出学习任务与固定任务，
  状态标签区分，无具体时间的任务不会被隐藏，排序稳定。

**v1.0.0 新增的能力**

- **首页作为主入口**：今日任务与真实进度、下一项学习、一键进入专注、未来七天概览，
  以及**生成/重新规划计划**（不再需要先进偏好设置）。
- **专注番茄钟**：专注/短休息/长休息、暂停继续、自定义时长、环境音；
  计时基于**真实时间戳**，刷新、切换标签页或电脑休眠都不会漂移。
- **固定专注功能栏**：计时进行中时出现在每一页底部，可以就地暂停、继续、放弃或回到专注页，
  不必在页面之间来回切换。
- **奖励转盘**：自定义奖项与四种触发规则，抽奖机会由真实学习记录推导，不会重复发放。
- **通知提醒**：浏览器权限与应用开关分开管理，4 种提醒、提前时间、跨午夜静音，刷新不重发。
- **学习统计**：今日/本周对比、近 14 天趋势、科目分布、任务完成率与逾期、专注轮数、成就。
- **外观主题**：浅色/深色/跟随系统 + 自定义壁纸（填充/适应/居中/平铺、模糊、遮罩）。
- **任务剩余时长**：可声明"已经在应用外完成的部分"，剩余时长仍是派生值。

## 二、安装与运行

### 环境要求

- 操作系统：macOS / Windows / Linux 均可。
- 浏览器：Chrome / Edge / Firefox / Safari 的较新版本。
- **无需安装任何 npm 依赖**（见下方"依赖政策"）。
- 开发与测试需要 Node.js **20 或更高版本**（推荐 22+）。

检查 Node 版本：

```bash
node -v
```

### 方式一：本地服务器运行（开发推荐）

ES Module 在 `file://` 下会被浏览器的同源策略拦截，因此请用内置的零依赖静态服务器：

```bash
node scripts/serve.mjs
# 或者指定端口
node scripts/serve.mjs 5173
```

然后在浏览器打开 <http://127.0.0.1:4173/>（默认端口 4173，脚本启动时会打印实际地址）。

服务器只监听 `127.0.0.1`，不对外开放，也不会发起任何联网请求。

### 方式二：单文件版本（可直接双击打开）

```bash
node scripts/build-standalone.mjs
```

会生成 `dist/standalone.html`（把全部 CSS 与 32 个模块内联进一个文件）。
直接双击这个文件即可在浏览器中使用，不需要服务器、不需要联网。

> 单文件版本与模块化版本功能完全一致。修改源码后需要重新执行构建命令。

### 运行测试

```bash
node --test "tests/**/*.test.js"           # 全部测试（489 个）
node --test "tests/unit/*.test.js"         # 领域层
node --test "tests/engine/*.test.js"       # 排程引擎（含 H1–H10 负向测试）
node --test "tests/integration/*.test.js"  # 服务层、预览闭环、界面业务流、界面冒烟、构建产物
```

如果使用 `pnpm`/`npm`，也可以直接用脚本别名：

```bash
npm test                 # 等价于 node --test "tests/**/*.test.js"
npm run serve            # 启动本地服务器
npm run build:standalone # 生成单文件版本
```

### 数据存放位置与备份

- 数据保存在浏览器的 `localStorage`（键名前缀 `studyPlanner:v1:`）。
- **清理浏览器数据 / 使用隐私模式会丢失计划**，请定期用界面上的"导出备份"保存 JSON 文件。
- 应用会在写入新数据前自动保留一份上一版备份；主数据损坏时会尝试从备份恢复并提示你。
- 导入会先完整校验，校验失败时**不会修改**你现有的任何数据。

## 三、依赖政策

本项目**运行时与测试均为零依赖**（v1.0.0 依然如此）：

- 界面使用原生 HTML / CSS / ECMAScript Module，没有引入任何前端框架或 UI 库。
- 排程相关的一切计算都是纯函数，不使用 AI 模型、AI API 或大语言模型。
- 测试使用 Node.js 内置的 `node:test` 与 `node:assert`，没有引入 Vitest/Jest。
- `package.json` 的 `dependencies` 与 `devDependencies` 均为空对象，并由自动化测试持续守护
  （见 `tests/unit/docs.test.js`：源码中出现外部包导入会直接测试失败）。

将来如确有必要引入依赖，必须遵守项目约定：先说明**包名、用途、必要性、替代方案、潜在影响**，
经项目所有者同意后再安装，并同步更新 `README.md`、`ARCHITECTURE.md`、`CHANGELOG.md`。

## 五、使用说明

1. 启动服务器并打开页面。
2. 进入**任务列表** → 点击"新建任务"，填写名称、科目、预计用时、截止日期与时间，
   以及可拆分规则与主观评估（重要程度 / 难度 / 拖延风险）。
3. 在**偏好设置**查看（当前通过 JSON 编辑区修改）可学习时间、拆分规则、休息规则、
   机动缓冲比例与优先级权重。修改前会先校验，校验失败不会写入任何数据。
4. 回到**今日总览**或**七天计划**，点右上角"生成计划"。
5. 在**调整预览**查看候选计划与差异明细，确认无误后点"确认应用"；
   不满意就点"放弃修改"（正式计划不会有任何变化）。
6. 在**七天计划**查看小时刻度时间轴与每日统计；在**调整预览**可撤销上一次计划变更。
7. 在**每日视图**逐日检查当天的时段，点任一时段可锁定、移动或取消（同样先生成预览）。
8. 在**固定活动**录入课程、睡眠、用餐、社团；删除前会显示能释放多少可用时间。
9. 在**偏好设置**用图形化控件调整可学习时间、拆分规则、休息规则与优先级权重。
10. 在**专注工作台**开始 / 暂停 / 继续 / 结束学习；结束时可选择只记录实际时长，或（先生成预览）重新规划剩余工作。
11. 在**版本历史**查看每个版本的变更说明并撤销；在**偏好设置**查看存储占用、导出备份、清理历史记录。
12. 在**七天计划**按列查看这一周（每列一天，学习任务可完成/删除）；用「上一周 / 下一周」翻周。
13. 在**每日视图**聚焦某一天；右上角「设置休息」可以记录今晚休息或设置每周固定睡觉时间。
14. 在**外观主题**切换浅色/深色/跟随系统，并选择本地图片作为壁纸。
15. 在**通知提醒**授权浏览器通知，选择提醒类型与提前时间。
16. 在**学习统计**查看真实学习时长、科目分布、任务完成率与成就（逐日柱状图：一天一根柱子）。
17. 在**偏好设置 → 科目管理**统一新增 / 改名 / 删除科目。

> 提示一：预览不会自动生效。只要不点"确认应用"，任务、设置与计划都不会被改动。
> 提示二：**每一项修改都会先生成预览**——包括新建任务、删除固定活动、调整权重。

## 六、常见问题与故障排查

**Q：刷新后数据会丢吗？**
A：不会。数据写入浏览器 `localStorage`，并且每次写入前都会保留一份上一版备份。但清理浏览器数据、
换浏览器或使用隐私模式会导致数据不可见，请定期导出备份。

**Q：为什么直接双击 `index.html` 打开是空白/报错？**
A：浏览器会因同源策略拦截 `file://` 下的 ES Module。请使用 `node scripts/serve.mjs`，
或运行 `node scripts/build-standalone.mjs` 后双击 `dist/standalone.html`。

**Q：为什么点"生成计划"后有的任务没有排进去？**
A：说明七天窗口内的可用容量确实不够。预览页会逐条说明原因（容量不足 / 尾部时长过短 /
   前置任务未完成 / 不可拆分任务放不下…），并给出可选处理方式（延长学习时间、调整最短时段、
   改截止时间、接受部分可行）。系统不会通过取消机动缓冲来掩盖超载。

**Q：会不会有 AI 参与排程？**
A：不会。所有排程、拆分、冲突判断与重新规划都由可测试的确定性算法完成，不调用任何 AI 模型或外部 API。

**Q：我的数据会被上传吗？**
A：不会。这是纯本地应用，没有后端、没有账号、没有任何网络请求。

## 八、数据与隐私

**数据存在哪里？会丢吗？**
数据只保存在你当前浏览器的本地存储里（键名前缀 `studyPlanner:v1:`）。清理浏览器数据、
换浏览器、换设备都会看不到旧数据，所以请定期在"偏好设置 → 数据与备份"里导出 JSON 备份。
页面顶部在"只读模式"（浏览器禁用本地存储时降级为内存）会显示明确横幅。

**刷新页面后计时会归零吗？**
不会。计时状态属于数据：暂停时会把已累计分钟数写进存储，进行中则按"开始 → 现在"推算，
两者取较大值。因此刷新后继续、忘记暂停都不会少算。

**计时为什么没有每秒跳动？**
只有"进行中且未暂停"时才注册每秒心跳。已暂停、还没开始、或已经离开工作台页面时不会刷新。
如果进行中依然不动，请确认页面没有被浏览器冻结（后台标签页的定时器可能被节流）。

**点了"确认应用"却说预览已过期？**
这是保护机制。预览生成之后，如果任务、时段、固定活动或设置又发生了变化，
确认时会拿"实时输入指纹"和预览时的指纹对比，不一致就拒绝应用，避免用旧计划覆盖新数据。
重新点一次"生成计划"即可。

**为什么我的任务没有被安排？**
打开调整预览页或七天计划页看原因码：
`insufficient_capacity`（可用时间不够）、`deadline_passed`（截止时间已过）、
`blocked_by_dependency`（前置任务没做完）、`non_splittable_no_slot`（不可拆分且没有合适长度的空档）等。
每条都会给出中文说明与建议。可到"偏好设置"延长可学习时间，或把任务改成允许拆分后重新规划。

**导入备份被拒绝了怎么办？**
导入分两步：先校验并给出摘要，通过后才允许写入。被拒绝时会逐条列出问题
（缺字段、类型错误、版本比当前新等），此时**现有数据一个字节都没有变**。
按要求修正 JSON 后重试即可。

**想彻底清空所有数据？**
在"偏好设置"里先导出备份，然后清除浏览器中该站点的本地存储
（键名 `studyPlanner:v1:state`、`studyPlanner:v1:backup`、`studyPlanner:v1:meta`）。
应用内不提供"一键清空全部"，是为了避免误操作导致无法恢复。

**测试怎么跑？**
`node --test "tests/**/*.test.js"`（Node 版本需支持内建测试运行器，本项目在 Node 24 上验证）。
单文件版本用 `node scripts/build-standalone.mjs` 生成 `dist/standalone.html`，双击即可打开。

## 九、新功能使用要点

### 为什么完成任务后，它的学习时段会一起消失
因为一段学习的"剩余工作量"必须始终大于等于"已排但未完成的时段"。
任务完成（或取消、删除）后剩余工作量为 0，那些还没做的时段就会被自动取消——
已完成的学习记录不会被动，它们仍然是你的学习历史。

如果只是想减少任务的工作量（例如从 120 分钟改成 60 分钟），改完之后超出的部分同样会被取消，
剩下的安排会重新规划。这正是"任务与计划始终对得上"的含义。

### 之前的数据出现了不一致怎么办
应用在**读取自己的数据**时会做一次安全检查：如果只是"任务与时段数量对不上"，
它会自动取消多出来的**未完成**时段，并在页面顶部说明改了什么；
已完成的记录一律保留。结构损坏等其它问题仍然会如实报错，不会被"修复"掩盖。
导入外部备份时不会自动修复——那种情况会直接拒绝并列出问题。

### 通知在什么情况下不会发送
- 你没点过"启用通知"，或浏览器权限被拒绝；
- 应用内的提醒开关关闭，或当前处于你设置的静音时段；
- **页面完全关闭**（浏览器不会执行本应用代码，这一点无法绕过，应用里也如实说明了）。

### 生成计划时的"开始时间"是什么
它只决定**这次从哪里开始找空档**，不是长期设置：
- 留空 → 从"当前时刻之后的下一个整点"开始（20:24 / 20:00 / 20:59 都取 21:00，21:00 取 22:00）；
- 填写 → 从你指定的时间开始；如果那个时间已经过去，会明确告诉你"已改为从 HH:mm 开始"；
- 无论哪种，都不会把学习安排到过去的时间里。

### 为什么完成/删除了任务，那个时段还是不能安排别的？
现在可以了。这是 v1.3.0 修掉的一个核心问题：
已完成或已删除任务的时段属于**历史记录**，不再是"当前有效占位"。
它继续留在统计里，但不会再阻止你把同一时间安排给固定课程或休息。

### 科目为什么要有"管理"而不是直接打字
以前科目是每个任务各自的自由文本，打错一个字就会永久多出一个选项，而且没法清理。
现在科目是一份统一列表：改名会让所有引用它的任务一起改名，删除前会先告诉你有多少任务在用。
旧任务里已经存在的科目会自动收进列表，不会丢。

### 为什么计划里点「删除任务」可以直接删掉
删除会用与任务列表完全相同的一套逻辑：先取消这个任务**未完成**的时段，
再按有无历史决定软删除还是彻底删除。因此不会留下"任务删了、时段还在"的孤立数据，
也不会因为"剩余工作量与时段数量对不上"被校验拦住——这一步在同一个事务里完成。

### 卡片大小是怎么定的
以 5 分钟为一个标准格：5 分钟 = 1 格、30 分钟 = 6 格、60 分钟 = 12 格。
卡片高度就是整数个标准格，所以 60 分钟的卡片恰好是 30 分钟的两倍高。
30 分钟以内的卡片用"紧凑排版"（只显示时间和名称），保证文字不溢出。
这套格子只用来对齐尺寸，不绘制任何时间刻度。

### 休息时间与固定任务有什么区别
固定任务是"不可移动的占用"（课程、睡眠），会影响排程与可用容量；
休息时间是你主动安排的放松，**不参与排程、不计入学习统计**。
一条跨午夜的休息（22:00 → 次日 08:00）在界面上会拆成 22:00–24:00 与 00:00–08:00 两块，
但底层仍然只有一条记录，改或删都会一起同步。

### 壁纸存在哪里
图片在你的浏览器本地（IndexedDB），并且会先压缩到最长边 2560 像素再保存。
不会上传到任何服务器，也不占用 localStorage 的 5 MB 额度。
显示方式固定为"填充窗口 + 半透明遮罩"——遮罩是保证任何照片下文字都可读的底线，因此不提供调节。

### 任务"已经完成"填了有什么用
很多学习发生在应用之外（纸质作业、线下课）。填上"已经完成 30 分钟"之后，
剩余时长会相应减少，排程不会再重复安排这部分；剩余时长本身始终是派生值，不会被单独存储。

## 十、已知限制

1. 界面自动化测试使用手写的打桩 DOM，不覆盖真实 CSS 布局与真实点击；
   这些由 `docs/ACCEPTANCE.md` 的人工步骤覆盖。引入真实 DOM 测试依赖需要项目所有者批准。
2. 时段移动通过表单完成，不支持拖拽绘制时间块。
3. 固定活动只能按规则编辑，没有"临时调整某一天"的入口。
4. 撤销之后没有"重做"。
5. 历史记录清理需要手动触发（不会自动删除用户数据）。
6. 重复规划会把被替代的时段保留为"已取消"，长期使用建议定期清理。
